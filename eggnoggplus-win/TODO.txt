    - Replace the custom rollback UDP harness with the production GGPO library/session

Netcode correctness and quality (open; the current rollback transport still has known
desync and recovery failure modes):
    - P0: Freeze and allocate the rollback-state layout only after the server-selected
      map and deterministic content are installed. Fingerprint a versioned schema, then
      validate the final layout (or a proven maximum) so different prior maps cannot
      cause false incompatibility or undersized buffers.
    - P0: Make remote-input confirmation monotonic. Track the highest contiguous confirmed
      frame, never let an older recovered/reordered packet replace the predictor command,
      and add explicit ACK/selective-resend state instead of relying on a newest-to-oldest
      64-frame packet window. Publish checksums and make correction/retirement decisions
      only at or below that contiguous confirmed horizon.
    - P0: Protect input rings with wrap-safe serial arithmetic and retention-window checks.
      Reject stale-below-retention and implausible far-future frames so a delayed packet
      cannot overwrite a newer generation that shares its 512-slot ring index.
    - P0: Never simulate beyond recoverable input or rollback history. Reconcile the
      64-input resend window, 512-state history, prediction cap, and stall timeout; pause,
      reliably recover, perform a coordinated resync, or disconnect before a permanent
      hole/history overwrite can occur.
    - P0: Redesign correction around a mutually confirmed-frame barrier. Snapshot only a
      confirmed frame, buffer and acknowledge subsequent inputs on both peers, apply the
      snapshot, then deterministically replay. Do not clear host history and continue from
      predicted state while the joiner rewinds later.
    - P0: Validate every correction blob's schema, size, canonical checksum, and transfer
      completeness before touching live state, then apply it transactionally with rollback
      on failure.
    - P0: Replace pointer-dependent raw memory slabs with a typed, versioned, pointer-free
      deterministic state schema. Store controller/player roles explicitly and require
      semantic save-load equality, not only byte-copy success. Loading must reconstruct
      dynamic entity cardinality and allocator metadata instead of requiring the live
      `thing_count` to match a snapshot across spawn/despawn/death.
    - P0: Checksum every simulation-affecting field, including gameplay RNG and every input
      to active-room selection; formally separate camera/audio/presentation state. Enforce
      one canonical x87/MXCSR environment around both live and replay ticks.
    - P1: Preserve the first divergent canonical snapshots and report component hashes plus
      the exact first differing field/entity/tile. Emit a secret-free per-session repro
      bundle with fingerprints, full input trace, network-chaos seed/events, FP controls,
      and RTT/jitter/loss/reorder/rollback/stall/correction counters; add a peer-trace diff
      tool.
    - P1: Expand paired automated sessions from prematch/one neutral tick to thousands of
      nonzero-input frames with prediction, rollback, frame wraparound, forced mismatch,
      correction, disconnect, entity spawn/despawn/death, and exact per-frame
      state/checksum assertions.
    - P1: Add seeded loss, burst-loss, delay, reordering, duplication, would-block, and
      bandwidth-limit matrices at the resend/history boundaries. Add native soaks across
      rooms, deaths, respawns, scoring, reset, hazards, custom maps, window/render variants,
      and differing floating-point modes; require bounded stalls and reproducible failures.
    - P1: Define local-input sampling across prediction/time-sync stalls so stale physical
      input is never assigned to an unintended future frame. Capture/canonicalize state
      once per frame and reuse it for history, checksums, and component diagnostics.
    - P1: Prioritize and pace input, ACK, heartbeat, and correction traffic with real
      backpressure; correction chunks must not starve current inputs, and local socket
      would-block/drop events must be counted instead of silently treated as success.
    - P1/P2: Replace service-tick RTT and fixed margins with monotonic sequence-aware
      RTT/jitter/loss measurements, safe-boundary adaptive input delay, and GGPO-style time
      sync with bounded replay/catch-up work instead of freeze-then-ignore behavior.
    - P2: Add established-match reconnect/resume, authenticated NAT rebinding, coordinated
      direct-to-relay failover, MTU discovery, congestion/pacing, and player-visible ping,
      jitter, loss, rollback, stall, and route health. Gate production GGPO integration on
      the deterministic schema/input protocol and seeded chaos suite above.

# Completed (source implementation and focused automated coverage)

    - Strict online control transport: atomic queued writes/backpressure, strict flat JSON,
      framing limits, independent connect/auth deadlines, secret cleanup, and complete
      all-or-nothing map manifests. A 30-second authenticated heartbeat keeps idle hubs
      and long matches alive across the server's receive-idle timeout. TLS remains the
      release blocker listed above.
    - Authenticated P2P UDP v16: per-match 256-bit tokens, directional HMAC-SHA-256/128,
      CSPRNG sessions, constant-time verification, replay window, and fail-closed key use.
    - Server match-protocol deployment guard: the client now requires a flat `server_info`
      capability handshake before login, rechecks auth/match version fields, and fails
      before queue/P2P setup on incompatibility. A public TCP+UDP preflight and isolated
      two-client runtime test prove that both peers receive one shared 64-hex match key
      and distinct probe keys. The coordinated match-v3 public server was backed up,
      atomically deployed, restarted, hash-verified, and checked on both listeners; the
      real two-game round remains in Runtime acceptance. Legacy unauthenticated fallback
      remains forbidden.
    - Bounded P2P connection retry: three fresh sockets/mappings, one deterministic
      server-selected loopback/LAN/public route per attempt, authenticated fresh-session
      recovery when only one peer rolls its socket, and clean hub recovery after exhaustion.
    - Prematch preparation behind the countdown: connection, native reset, state transfer,
      and neutral frame zero complete before GAME is shown. Match protocol 3 keeps both
      clients behind the hub until each reports a restorable frame zero and the server
      commits gameplay; every pre-commit timeout, abort, disconnect, stale setup, or
      premature result is a no-contest instead of a fake win/loss.
    - Online simulation through the audited pause/options/console/Mods overlays, with menu
      input neutralized and both local control sets merged into the assigned fighter.
    - Server-managed build/map compatibility gates and automatic suspension/guarding of
      framework-managed gameplay Lua for the full match lifecycle.
    - Custom online result state with server-confirmed outcome/rating text, responsive
      Requeue/Hub keyboard, controller, and mouse actions, stable hub return ownership,
      fail-safe rejection of stale/inactive result transitions, and committed-game-only
      result admission so failed setup returns directly to one stable hub state. Normal
      results now require two reports naming the same winner; unilateral timeouts and
      conflicts are no-contests with no Elo change. A commit plus immediate forfeit result
      in one TCP batch resolves directly without entering a server-deleted GAME.
    - V2 custom-map parser and declarative content tile bridge: symbolic cells, per-map
      atlases, validation, animation/tint/transform/layers, atomic reload, native fallback,
      generation-safe retirement, and Lua registry API. A selectable demo now covers an
      external animated atlas, built-in transform/layer, deliberate fallback, and mirrored
      rooms, with a one-command package/parser regression test. External PNG bytes are
      always hashed into map/online identity; `asset_sha256` is only an optional package
      integrity pin, not a hand-maintained authoring requirement.
    - General window policy source repair: F1 3:2 presets, F11, maximize normalization,
      display-aware fullscreen cache, safe event-boundary recreation, desktop borderless,
      launch-flag conflict handling, and local-only viewport refresh.
    - Secure opt-in credential implementation: exact server/account Windows Credential
      Manager targets, save only after `auth_ok`, deletion on opt-out/rejection/identity
      change, malformed-record cleanup, and secure memory clearing. A valid remembered
      account now authenticates automatically, hides the login form while pending, and
      opens directly into the hub menus with backend-neutral player-facing copy.
    - Exact native framework cursor integration: the fake built-in cursor and later
      white/custom-scale approximation were removed. Online UI, automatic custom-state
      cursors, and no-option `mod.ui.draw_cursor()` now share the game's actual two-pass
      renderer with native global scale, shadow, pulse color, hotspot, and state restore;
      online still queues it only once/topmost. Live acceptance remains listed above.
    - Framework version checking: asynchronous launch check, live Mods-menu
      status/retry/install actions, and a bounded dismissible update notification.
    - Automatic transactional framework updates: default-on, SHA-256/size verification,
      bounded downloads, reserved-namespace path safety, V2 integrity journal,
      complete-set verified roll-forward, conservative rollback/quarantine recovery,
      single-writer locking, and restart-required status. The isolated one-command test
      runs a real loopback apply plus reduced-journal and recovery regressions entirely in
      disposable build directories. The direct-import helper gap remains in Feature
      backlog instead of being described as power-fail-safe.
    - Atomic updater-owned config writes that preserve comments and unrelated settings;
      main-menu mode persistence now uses this API instead of rewriting a fixed buffer.
    - Configurable Lua cursor options for deliberate custom sprite/index, scale, hotspot,
      tint, and layer choices, including per-state automatic/disabled/custom policies.
    - Custom-map water ambience/effects: native water glyphs, per-room water colors,
      bubbles, boil, and fume ambience.
