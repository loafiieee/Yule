Docs / API / Map Lua

Deterministic map.lua

A V2 package may place one map.lua beside data.json and data.map. The restricted VM adds bounded tile contact behavior without filesystem, network, OS, UI, audio, dynamic code, modules, FFI, debug, or process access.

Custom objects and physics: current boundaries

Custom objects are framework-owned instances declared in entities.json. Their callbacks share this map's Lua VM. They are not native EGGNOGG thing slots: they do not automatically inherit native gravity, terrain collision, sword combat, or corpse behavior. Validated packages can play online when both peers advertise the identical map-package signature.

entity.on_update(type, callback), entity.on_spawn, entity.on_contact, entity.on_player_contact and entity.on_remove register lifecycle callbacks. Use entity.get(handle) and entity.set(handle, {x=..., y=..., vx=..., vy=...}) for fixed-point movement. Live objects integrate velocity once each simulation tick. Coordinates and velocity use pixels and pixels per tick; writes round to 1/256 pixel.

Greggnogg's Object designer supplies gravity, horizontal drag and maximum vertical speed controls. These generate update logic before your authored callback body. Enable Collide with solid map blocks to stop at native solid tiles, using the centered collision width and height. Movement is swept along X then Y; it does not bounce or damage players. Custom update logic runs afterward and can override the resulting velocity. Start objects clear of terrain. Advanced Lua can implement other movement rules within the VM's shared execution limits.

API 23 adds map.solid_box(x, y, width, height): a gameplay-only query returning whether a centered box overlaps native solid terrain. Dimensions are 1/256 through 128 pixels; coordinates must be within +/-4194303 pixels. Map boundaries are solid; merely touching an edge is not overlap. Each query consumes execution budget. This does not query players or custom objects.

Block variables

Map and Object logic share named map-wide and per-player variables. The Blocks Variables category reads, sets, changes, clears and tests existence. Values live in map.state under v:m:NAME or v:p:NUMBER:NAME, persist across ticks and restore with rollback. Unset reads return 0; boolean false is preserved. The shared state capacity is 64 entries. Player input events and player-following indicators are not yet provided by these blocks.

API 24 adds entity.set(handle, {automatic_motion=false}) to disable velocity integration while preserving explicit position writes and animation. New Greggnogg designs use this mode.

Per-object variables (API 29)

Each managed object has independent rollback-owned values. Use entity.value(handle, name), entity.set_value(handle, name, value), entity.change_value(handle, name, delta), entity.has_value(handle, name), entity.value_keys(handle), and entity.clear_values(handle). Names are 1-32 bytes without NULs. Values are nil, boolean, finite number, or strings up to 63 bytes; assigning nil deletes one value. The package has 512 object-value entries, separate from the 64 shared map.state entries.

Values follow the exact generation-aware handle, so two instances can use the same name without sharing data. An on_remove callback may inspect the departing object's values; the runtime clears them after that callback succeeds. Callback failure restores both the entity and its values. value_keys returns a detached, bytewise-sorted list. Greggnogg's this object variable scope generates these calls automatically.

Custom solid query (API 27)

entity.solid_box(x, y, width, height [, ignored_handle]) tests a centered rectangle against custom Solid regions, excluding an optional live instance. It returns a boolean; edge-only contact is false. Dimensions range from 1/256 to 128 pixels. Coordinates and dimensions round to 1/256 pixel. Queries consume execution budget. Greggnogg physics combines this query with native terrain detection and excludes the moving object's own regions.

Object point query (API 26)

entity.at(x, y) returns a detached, stable-order list of handles whose authored regions contain the world point. Each instance appears once. Left/top edges are included; right/bottom are excluded. All region purposes participate and mirroring is applied. Empty-region objects do not match. Results may include the caller; use entity.type and ordinary conditions to filter them. Work is charged to the shared execution budget.

Exact authored tile query (API 28)

map.tile_at(x, y) returns the one-character source symbol at a world-space pixel coordinate. It reports custom V2 symbols exactly as authored, rather than substituting their native collision glyph. Mirrored outer rooms map back to their authored source cells. The function returns nil outside the complete map, is available only during gameplay callbacks, and charges each lookup to the shared execution budget.

Greggnogg exposes this together with entity.at as one at x/y is [tile or object] block. Its picker contains native tiles, custom tiles from the current map, and current-map object designs. Combine several conditions with ordinary OR blocks to match any desired set.

Named detection areas (API 30)

Each object detection area may have an optional local name of 1-32 lowercase letters, numbers, underscores, hyphens, or periods. Names must be unique within one object design. entity.regions(handle) includes that name on the returned region, while older unnamed areas omit the field.

Names identify a particular shape independently of its purpose. For example, a design can name sensors feet and vision, then test region.name == "vision" even if both use the sensor purpose. Greggnogg's player/object touching block lists the names belonging to the current object. Region names are validated by both the editor and native loader and participate in the package fingerprint.

Player input, ground state and object visibility (API 31)

map.players() now includes grounded and previously_grounded, plus detached input, pressed and released tables. Each input table has boolean attack, jump, right, left, up, down and menu fields. Pressed and released are edges between the rollback-owned pre-tick command and the current native tick. Changing these returned tables does not change player input.

Managed object placements accept optional visible: false and entity.set(handle, {visible = boolean}) can change it later. entity.get(handle).visible reports the current value. Visibility only controls drawing: hidden objects still update, keep state and use their authored sensor or solid regions.

A placement can initialize the same general presentation state with animation, scale_x/scale_y, visual_offset_x/visual_offset_y, visual_rotation in degrees, visual_tint: "#RRGGBBAA", and draw_layer: "behind" or "front". Greggnogg exposes these settings in the normal map editor's Object inspector after selecting a placed custom tile.

The checked-in maps/double_jump_demo package uses these general primitives for one extra airborne jump, a per-player indicator and a collectible recharge. Its map and object behavior are saved as editable Greggnogg blocks; it does not rely on a dedicated double-jump command.

Object and player contacts (API 32)

entity.player_contacts([handle [, selector]]) returns authored regions touching live players. Limit it to one handle and select any, a purpose such as hitbox, a named area such as name:attack, or a positive region ID. Results are detached and ordered by object slot, region declaration and player number. Each record has entity, region, optional region_name, role, player, motion, radius, ground state and input tables.

entity.on_contact(type, callback) receives object/object region contacts. Its record includes other, other_type, both region IDs, optional names and purposes. entity.on_player_contact receives the player-contact record. The runtime captures all contacts after movement and before calling either group. A failure restores managed state and discards queued native player velocity/defeat writes.

Greggnogg exposes both lifecycle events in Object logic. The current-area, other-area and other-object blocks filter contacts; ordinary this-player blocks refer directly to the player in a player-contact event. Area purposes remain descriptive: scripts decide whether a contact damages, collects, pushes, removes, spawns or changes state.

Managed object damage events (API 33)

entity.damage(target, amount [, source]) synchronously sends a deterministic attempt to a live managed object. It returns true when the target has a damage filter, managed health, or an entity.on_damage callback. The callback receives (target, damage). The detached damage record always has a finite positive amount and, when supplied, a live source handle and source_type.

Optional managed health supplies current/maximum health, healing, invulnerability and defeat callbacks. Register entity.on_damage_filter(type, callback) to inspect the attempted amount and optional managed-object source before health changes. It must return true to accept the hit or false to reject it. Rejected hits still reach on_damage with blocked = true and applied = 0. Calls are gameplay-only, share the execution budget, preserve deterministic caller order and allow at most 32 nested lifecycle callbacks. Callback failure restores managed state and discards queued player changes. Greggnogg provides before-damage, allow-damage, damage-event, amount and source blocks. Native kicks, swords, spike balls and mines are not yet converted into typed managed damage.

map.trigger_mine_at(x, y) queues a native mine activation at finite world coordinates. Requests execute only after the complete Lua transaction succeeds, are limited to 32 per tick, and exact duplicates return false. Production verifies that the coordinate currently contains native mine tile 0x06 before calling EGGNOGG's own trigger path, so another tile action cannot run. Greggnogg provides a matching coordinate action block.

Spawn-time object values (API 34)

entity.spawn(type, properties) now accepts values = { name = value, ... }. Up to 32 object variables are installed on the new exact-generation handle before its on_spawn callback. This supports reusable projectiles and equipment-like objects configured with an owner, damage, team, cooldown or other scalar data. Values use the normal object-variable limits and consume the package-wide 512-entry capacity.

Spawn returns the new handle. Invalid initial values, capacity exhaustion, or callback failure abort the enclosing transaction without leaving a partial object. Greggnogg provides a configured-create block for one variable plus a this object's handle value; Advanced Lua can fill the full table.

Managed object signals (API 35)

entity.signal(target, name [, value [, source]]) synchronously delivers a general authored message to a live managed object. One entity.on_signal(type, callback) receiver may be registered per type. The callback gets (target, signal); the detached record has name, optional scalar value, and optional live source/source_type fields.

Names start with a lowercase letter and contain at most 32 lowercase letters, numbers, dots, underscores, or hyphens. Calls are gameplay-only, consume shared execution budget, preserve synchronous caller order, and participate in transaction rollback. Use signals for switches, pickups, equipment, weapons and authored state machines. Greggnogg provides receiver, sender, name, value and source blocks, plus text values for name comparisons.

Room doorway locks (API 36)

Room-graph connections are numbered from 1 in the same order as layout.connections. map.set_exit_locked(connection, locked) changes one doorway's deterministic lock state, and map.exit_locked(connection) reports it. A locked connection refuses traversal in both directions; one-way direction still applies after it is unlocked. Locks are available for all 256 connection slots, have their own rollback storage, and do not consume map.state entries. They default to unlocked and fail open if map logic is disabled.

Greggnogg numbers the doorway rows in Rooms mode and exposes those same labels in the Game block group as set Door … to locked/unlocked and Door … is locked. Blocks save the connection's stable editor ID and compile it to the current native number, so deleting an earlier doorway does not silently retarget them. Handwritten Lua uses numbers directly and must be reviewed after connections are reordered.

map.room_count() reports the immutable placed-room count, map.start_room() returns the zero-based starting room (or nil for an empty layout), and map.room_info(room) returns detached room metadata. Its common fields are room, id, source_room, source_id, placed, and start. Room-graph entries also include normalized world-pixel x, y, width, height, and mirrored. The zero-based number matches player room observations on graph maps, avoiding coordinate-based room guesses in portals, checkpoints, and room-specific rules.

map.move_player_to_room(player, room, local_x, local_y) moves a player during a tick, timer, or entity-update callback. The room is a zero-based placed-room number and the pixel position is local to that room. Yule validates the point and commits the translated world position and native room number together for consistent transitions, camera state, and rollback.

Camera drawing

In a gameplay callback, map.set_camera_point(x, y, zoom) fixes the rendered camera at a world-pixel point with zoom from 0.25 to 4. Coordinates are bounded and rounded to 1/256 pixel; zoom is rounded to 1/256. map.clear_camera() returns to the native camera, while map.camera_override() returns a detached table with x, y, and zoom, or nil when inactive. This changes drawing only, not physics, room transitions, or respawn rules. The camera state participates in rollback. Greggnogg exposes point, release, and readback blocks in Game. Follow targets, animation, bounds, and shake are not yet authored camera features.

Solid obstacles (API 25)

A region with role: "solid" blocks native players, corpses, swords and hazards. Greggnogg exposes this as the area's Solid checkbox. Geometry uses authored rectangle bounds, mirrored with its object; sprite scaling does not scale collision. Native body motion is swept against an expanded rectangle, stops on the blocked axis and slides along the other. Use separate sensor/attack regions for event filtering. This does not add moving-platform carrying or custom-entity rigid-body collisions.

What detection areas mean

Body, sensor, hitbox and hurtbox are authored region roles. An area alone does not stop movement or damage a player. entity.regions(handle) returns local and world bounds; entity.contacts() queries object/object region overlaps. map.players() supplies live player positions, speeds and contact radii. Logic must choose the response. Greggnogg's player/object touching block uses entity.player_contacts against a chosen purpose or named area.

During tick, entity-update or entity-contact callbacks, map.set_player_velocity(player, vx, vy) queues native velocity changes, map.set_player_position(player, x, y) queues a checkpoint/portal move, and map.defeat_player(player) queues native death. Player numbers are 1 and 2. All commit after successful script execution; callback failure discards the batch. A position change also translates the native previous position, preventing false one-frame motion after a teleport.

Health is optional. Greggnogg's Object designer has a Health and damage section for maximum and starting health. Managed objects use entity.enable_health, entity.health, the health setters, entity.heal, and entity.damage. Damage subtracts managed health automatically; entity.on_defeated runs on the transition to zero and chooses whether to animate, transform, disable, or remove the object. entity.set_invulnerable blocks applied damage while preserving damage attempt callbacks, entity.invulnerable queries it, and entity.disable_health opts out of managed health.

Verified native attacks use the same object damage pipeline. Punches deal 12, kicks deal 25, and held swords, thrown swords, K spike balls, and mine blasts deal 100. Their damage.source_type values are native:punch, native:kick, native:sword, native:thrown_sword, native:spike_ball, and native:mine. The Object designer exposes each source as a checkbox. Attacks test Damage receiver areas and fall back to Body areas. Held-sword damage follows the engine's attacking probes; an idle sword resting or blocking against an object does not deal damage. entity.was_hit_by_player(handle, player) reports an accepted, nonzero player hit during the current tick. Player-owned attacks include damage.source_player as 1 or 2; spike balls and mines omit it.

Mine damage is emitted only when the native explosion callback accepts the blast; arming a mine does not deal damage. Call entity.set_mine_knockback(handle, true), or enable Knocked away by mine explosions in the Object designer, to apply EGGNOGG's 32-pixel radial impulse and distance falloff. This setting works without managed health and independently of the mine-damage checkbox. entity.mine_knockback(handle) reads it.

Native players use map.enable_player_health, map.player_health, map.set_player_health, map.set_player_max_health, map.damage_player, and map.heal_player. Register map.on_player_damage, map.on_player_health_changed, or map.on_player_defeated for reactions. Lethal damage queues ordinary native defeat. All health state and effects participate in rollback. map.set_player_invulnerable temporarily blocks damage, map.player_invulnerable queries it, and map.disable_player_health restores native unmanaged health behavior. Damage events distinguish requested amount from actual applied damage and report blocked.

Player snapshots also expose numeric native_state, room, facing (-1 left, 0 neutral/unknown, 1 right), complete current/previous collision_flags, and the synchronized skin_palette/clothing_palette indices. These are detached, read-only observations suitable for conditions and diagnostics. The boolean has_sword reports native weapon ownership directly.

map.set_player_presentation(player, options) can set body_visible and separate skin_tint/ clothing_tint RGBA multipliers during gameplay callbacks. Use "default" for one field or map.reset_player_presentation(player) for all fields. These draw-only values participate in rollback and are reported by map.players(). Player sprite replacement, animation, scale, offsets and draw layer are available through the dedicated replacement renderer: map.set_player_sprite(player, object_type, animation, restart, restore) reuses any validated custom-object picture and its authored transforms; set restore to true for a once animation to return to the native body on its deterministic completion tick. Loop and ping-pong animations reject automatic restore because they do not finish. map.clear_player_sprite(player) restores the native body. The replacement follows native motion without changing collision or combat. map.player_sprite(player) returns its object type, animation, resolved sprite cell, elapsed animation tick, frame/count, playback mode, completion state, one-tick just_finished edge, and automatic restore policy, or nil for the native body. map.set_player_sprite_transform(player, options) controls independent X/Y scale, offsets, rotation, tint, draw layer, animation speed, visibility and horizontal mirroring; map.reset_player_sprite_transform(player) restores the object picture's authored transform.

Additional entity controls include animation_tick, animation_speed, animation_paused, visual scale_x/scale_y, visual_offset_x/ visual_offset_y, visual_rotation, visual_tint, draw_layer, mirrored and visible. Tint accepts #RRGGBBAA or default; draw layer accepts authored, behind, or front. The type's authored visual.rotation and per-instance visual_rotation add together. Mirroring negates the combined angle; rotation changes drawing only and leaves authored regions axis-aligned. Object types can define arbitrary named animation clips with loop, once, or ping-pong playback. Use entity.play_animation(handle, name [, restart]), entity.animation(handle), and entity.animation_status(handle). The status table includes the zero-based frame, frame count, mode, tick, and a finished flag for play-once clips. entity.on_animation_finish(type, callback) receives the object and detached status once at that boundary, in stable object order. Full native rigid-body behavior is not exposed by this version. Use map.state for shared persistent logic and the object-value API for per-instance state. Managed entities and script state participate in rollback. Matchmaking compares a 128-bit package signature covering map/config, scripts, entities and external assets; P2P preflight then validates layout and the full managed-content identity before frame zero.

Execution model

  • The loader discovers one direct non-reparse map.lua; JSON does not name it.
  • The retained source and canonical tile bindings are part of map identity and online compatibility.
  • Callbacks cannot capture upvalues. Persist shared values in map.state and instance values with entity.set_value.
  • Contact order is deterministic: top-to-bottom, left-to-right map order over one immutable pre-callback physics sample.
  • A callback fault restores its partial object/tile/state changes, disables script behavior, and leaves native collision/render fallback active.
  • Script state, private RNG, tick clock, contacts, velocity limits, and sprite overrides participate in rollback.
  • map.random(min, max) accepts either endpoint order and returns an inclusive deterministic integer.

Complete spring and fan

map.sensor(">", {
  tile_box={left=0, top=0, right=1, bottom=.375},
  object_box={left=-.375, top=0, right=.375, bottom=.375},
  objects={"alive_player", "sword"},
  contact_scope="binding"
})

map.on_enter(">", function(object, tile)
  local launch = object.kind == "player" and -4.0 or -2.8
  object:set_velocity(object.vx, launch)
  object:set_velocity_limits({min_vy=launch}, 8)
  tile:set_sprite(129, 16, {offset_y=8})
  map.state.spring_hits = (map.state.spring_hits or 0) + 1
end)

map.sensor("}", {
  object_box="body",
  objects={"alive_player", "sword"},
  contact_scope="binding",
  mirror_with_room=true
})

map.on_contact("}", function(object, tile)
  local push = tile.mirrored and -0.25 or 0.25
  object:add_velocity(push, 0)
end)
