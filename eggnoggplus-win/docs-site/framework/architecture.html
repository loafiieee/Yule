Framework internals

Architecture

Yule is a 32-bit native DLL proxy around a fixed Eggnogg+ executable. It forwards SDL, installs narrowly scoped hooks, and exposes safer high-level services to isolated Lua mods.

Startup flow

eggnoggplus.exe
  └─ loads local SDL2.dll (Yule proxy)
       ├─ loads SDL2_real.dll (original SDL implementation)
       ├─ forwards the exported SDL API
       └─ initializes framework code after loader-safe startup
            ├─ native hooks and state adapters
            ├─ Lua mod manager
            ├─ custom content and assets
            ├─ console and framework menus
            ├─ online control + rollback transport
            └─ updater, Discord, audio, logging, and launch IPC

dllmain.c is the proxy entry boundary, while stubs.c and SDL2.def provide export forwarding. Expensive initialization, worker shutdown, and updater waits must not occur under the Windows loader lock.

Native hooks

hooks.c bridges known functions and state addresses in the supported executable: events, game ticks, rendering swaps, menus, player commands, maps, presentation, and online lifecycle. The addresses come from reverse engineering and are version-specific.

Small modules keep platform or subsystem responsibilities separate:

  • cursor_ext, font_ext, and texture_ext wrap presentation integration.
  • net_ext supplies bounded sockets, DNS, adapter routing, and probes.
  • credential_ext, launch_request, and launch_ipc isolate Windows credential/deep-link boundaries.
  • fp_control normalizes floating-point state for deterministic simulation.
  • rollback_schema describes and hashes the authoritative game-state regions.
Compatibility consequence: a different Eggnogg+ executable can move code or data. “It launches” is not proof that every hook is safe; ports need address and schema verification.

Lua runtime

lua_manager.c discovers manifests, resolves dependency order, creates one environment per mod, and owns callbacks and APIs. Environments fall back to standard Lua globals but do not share ordinary globals with each other.

The manager also tracks which capabilities a mod uses. Presentation-only callbacks can remain active where safe, while gameplay-affecting mods are suspended for online rollback. Cross-mod services use versioned mod.interop snapshots rather than accidental shared globals.

Custom content

  • custom_maps parses legacy and V2 map packages.
  • content_registry validates stable content declarations and fingerprints.
  • content_tiles and content_bridge connect symbolic/custom tiles to native rendering and physics behavior.
  • map_script runs bounded map-local Lua behavior.

Asset packing respects the engine’s fixed global sprite capacity. Map and content fingerprints are part of online compatibility; both peers must agree.

Online layers

Online hub UI
  └─ online_control: framed TCP account/matchmaking protocol
       └─ server rendezvous and match assignment
            └─ ggpo_net: authenticated UDP peer/relay transport
                 └─ ggpo_ext + rollback schema: predict, save, load, resimulate

The control connection and gameplay transport are distinct. Matchmaking exchanges bounded connection material; gameplay runs through authenticated UDP with direct candidates and server relay fallback. Input prediction and rollback use serialized authoritative state, while cosmetic state is excluded or repaired separately.

Threading and nonblocking work

The game/render thread owns native state and Lua callbacks. Network clients, update checks, audio producers, and Discord IPC are designed to pump or work asynchronously without waiting inside gameplay. Results cross bounded state machines and queues. A subsystem must not call unsafe game code from a worker or block DllMain.

Failure policy

  • Parsers use explicit size and count limits.
  • Online and update data fail closed when authentication, hashes, paths, versions, or state transitions are invalid.
  • Updates journal the whole file set and prefer retaining evidence over guessing through ambiguous recovery.
  • Optional services such as Discord and update checks degrade without stopping gameplay.
  • Logs identify a subsystem and avoid credentials or private match material by design.
