Framework internals

Building from source

The supported build is a 32-bit Windows DLL produced with MinGW. The script links a temporary proxy first and only copies verified artifacts into the runnable root after success.

Get the public source

git clone https://github.com/loafiieee/Yule-src.git
cd Yule-src

The public repository starts with clean history and includes the native framework, online server/admin/LFG/redirect services, installer/updater source, examples, documentation, and tests. It intentionally excludes the Eggnogg executable, redistributable runtime DLLs, generated builds, player configuration, account/rating databases, logs, and deployment secrets. You do not need private-repository access to inspect, build, test, or deploy the source services.

Prerequisites

  • The public Yule-src checkout. A legitimate Eggnogg installation is required only to run the resulting framework, not to compile the source tests.
  • MSYS2 with the 32-bit MinGW toolchain at C:\msys64\mingw32\bin.
  • 32-bit LuaJIT headers/import library available to MinGW; the script includes /mingw32/include and links -lluajit-5.1.
  • PowerShell, Python, and Node.js for the full mixed-language test suite.

The code links Windows system libraries for sockets, adapter inspection, HTTP, cryptography, credentials, dialogs, shell integration, and OpenGL. Third-party QuickJS-NG source is compiled into the DLL.

Compile

  1. Close Eggnogg+ and the updater. Windows cannot replace a DLL mapped by a running process.
  2. Open an MSYS2 shell in the repository root, or call Bash with the 32-bit MinGW tools available.
  3. Run the build: 
    bash compile.sh
  4. Confirm output. The script builds build/YuleUpdater.exe, rejects unsafe runtime imports, copies it to the root, links build/SDL2_test.dll, then copies that exact artifact to root SDL2.dll.

compile.sh uses strict shell behavior and a complete source list. If a new .c module is added, add it to the script’s sources or vendor_sources list and add every required link library.

Use guarded test runners

Never launch a MinGW test executable from build/ by hand. The guarded runners prepare the 32-bit runtime DLL search path and preflight dependencies, avoiding a storm of missing-DLL dialogs.

With the game closed, run from the repository root:

powershell -NoProfile -ExecutionPolicy Bypass -File tests/run_core_native_tests.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/run_v2_map_test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/run_map_script_test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/run_updater_test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/run_update_helper_test.ps1

These runners prepend the repository root, C:\msys64\mingw32\bin, and C:\msys64\usr\bin to child PATH as needed. They do not launch the game. A new native runner must provide the same safety boundary.

What the baseline covers

The guarded suites cover parser limits, content/tiles/maps, map Lua, state serialization, rollback and network envelopes, control protocol, credentials, deep links and IPC, updater staging/recovery, Discord IPC, bytebeat/JavaScript audio, and supporting static integration contracts. Live game acceptance still matters for hooks, visuals, audio devices, production Discord, real peers, and production HTTPS.

Common build failures

FailureResolution
32-bit GCC not foundInstall/repair MSYS2 MinGW32 or put C:\msys64\mingw32\bin on PATH.
LuaJIT header/library missingInstall the matching 32-bit development package; do not mix 64-bit libraries into this build.
Copy to root SDL2.dll failsClose every game instance using that exact installation, then retry. The linked test DLL remains in build/.
Undefined referenceAdd the implementation source or appropriate library in compile.sh; keep ordering/32-bit architecture consistent.
Test executable shows missing-DLL dialogsStop launching it directly and use its guarded PowerShell runner.

Build a release

Maintainer workflow. A playable release also needs the separately managed runtime payload and update channel. Those files are intentionally absent from public source and should not be reconstructed from secrets or copied out of a private deployment.

Maintainer release publication has stricter version and hash checks. After changing FRAMEWORK_VERSION, closing the game, compiling, and passing tests:

powershell -ExecutionPolicy Bypass -File .\tools\build_release.ps1 `
  -Version 1.2 `
  -Notes "Short release notes"

The version argument, compiled marker, source version, root DLL, and verified build artifact must agree. Upload the complete versioned payload directory first and publish latest.json atomically last. Follow UPDATER.md rather than reusing a retired version or hand-editing the channel around a mismatch.

Live verification

Automated tests intentionally do not launch eggnoggplus.exe. Use the checklist in source TESTING.md for an explicit manual pass: framework menus, mods, maps and map Lua, music, online matchmaking/routes/results, deep links, Discord, update UI, and recovery in a disposable release copy.
