Framework internals

File layout

The repository is also a runnable development game folder. Keep source, generated build output, runtime state, and release artifacts conceptually separate even though they live nearby.

Runtime root

eggnoggplus-win/
├─ eggnoggplus.exe          game executable
├─ SDL2.dll                 Yule proxy
├─ SDL2_real.dll            original SDL implementation
├─ lua51.dll                LuaJIT runtime
├─ libgcc_s_dw2-1.dll       MinGW runtime
├─ libwinpthread-1.dll      MinGW thread runtime
├─ SDL2_mixer.dll           optional/native audio backend
├─ YuleUpdater.exe          one-shot updater helper
├─ data/                    base-game data and tune files
├─ maps/                    custom map packages
└─ mods/                    mods, configuration, logs, runtime data

Launch the executable from this root so relative data/, maps/, and mods/ paths resolve to the intended installation. Yule’s deep-link handoff also roots work to the installed executable instead of the caller’s current directory.

The mods folder

mods/
├─ modframework.cfg         framework-wide preferences
├─ online_hub.cfg           non-secret online preferences
├─ modframework.log         main runtime log
├─ updater.log              updater/recovery status
├─ crash.log                crash handler output
├─ desync_dump.log          rollback mismatch evidence
├─ console_history.txt      developer-console history
└─ my_mod/
   ├─ mod.json              strict manifest
   ├─ main.lua              entry named by the manifest
   ├─ config.cfg            optional user settings
   ├─ storage.cfg           optional/default persistent state
   ├─ binds.cfg             optional/default named binds
   ├─ lib/                  mod-owned Lua modules
   └─ assets/               mod-owned images/audio/data

Folders beginning with _ are ignored by normal mod discovery. Bundled examples include options_demo, speedhack, and ai_opponent.

The maps folder

A map folder normally contains map data and may contain V2 metadata, a map-wide tileset, and bounded map-local Lua:

maps/my_map/
├─ data.map                 room/tile data
├─ data.json                V2 declarations and metadata
├─ tiles.png                optional map-wide tileset
└─ map.lua                  optional bounded behavior

Refer to the source MAP_FORMAT.md before authoring: accepted cell sizes, symbolic tile declarations, script APIs, fingerprints, and hot-reload behavior are more precise than filename convention alone.

Development folders

  • tests/ — native, Python/static, Node, and guarded integration tests.
  • tools/ — release builder and diagnostic utilities.
  • dist/installer/windows/ and dist/installer/linux/ — platform-specific installer/uninstaller templates and artwork.
  • online_server/ — matchmaking/control server, Discord LFG bot, deployment tests, and update script.
  • third_party/ — vendored source such as QuickJS-NG.
  • ghidra/ and eggnogg.gpr — reverse-engineering references; not runtime payloads.
  • docs/ — internal design specifications and plans.
  • docs-site/ — this hostable static documentation website.

Generated output

  • build/ holds compile/test intermediates, including SDL2_test.dll. Do not run its executables directly.
  • dist/ holds generated release channels and installer packages.
  • The root SDL2.dll and YuleUpdater.exe are installed development artifacts copied only after successful linking.
Dirty-worktree rule: runtime logs, configs, map edits, and local mods may be intentional user data. Do not bulk-delete or reset them while changing source.
