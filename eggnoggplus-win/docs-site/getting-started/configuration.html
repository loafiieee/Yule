Getting started

Configuration

Yule separates framework-wide preferences, online-account settings, and each mod’s own settings. Most everyday changes can be made in-game.

Prefer in-game settings

Open Options → Mods. The Framework section owns general toggles and updater actions. Each enabled mod with a config entry in its manifest gets its own settings section. The online hub has a separate Settings tab for online-specific choices.

In-game changes update live state and use the framework’s persistence helpers. Close the game before hand-editing files so an in-game save cannot overwrite your edit.

Framework configuration

mods/modframework.cfg is a simple key=value file. Unknown lines and comments are preserved by framework setting updates.

KeyMeaning
show_log_console=0|1Show or hide the separate Windows log console. File logging remains active.
main_menu_mode=play|online|<mod id>Remember the mode selected on the main PLAY button. Mods may register additional stable IDs.
auto_update=0|1Allow automatic update checks and installation prompts. If absent, automatic updates are enabled.
update_channel_url=https://…Override the release channel. Ordinary players should keep the release default.
music_output_rate=48000Set the SDL mixer device rate from 8,000 through 192,000 Hz. A track may temporarily override it.
discord_presence=0|1Enable or disable the dependency-free Discord desktop Rich Presence client.
discord_application_id=<digits>Public Discord Application ID. This is not a client secret.
Do not paste secrets here. This file is ordinary text. Online credentials are handled separately and should never be placed in framework config or logs.

Online hub configuration

mods/online_hub.cfg contains non-secret online preferences:

# Example only
username=your_name
remember_me=1
server_host=example.com
server_port=47778
local_port=0
challenge_notifications=1
  • server_host and server_port select the matchmaking/control server.
  • local_port=0 lets Windows choose an available local port and is the usual choice.
  • remember_me controls whether the supported credential store is used.
  • challenge_notifications controls incoming challenge notifications.

The active connectivity command reads this target:

online.troubleshoot

Per-mod configuration

A manifest can name a line-based configuration file such as config.cfg. Supported values are booleans, integers, floats, strings, fixed options, and action buttons:

enabled: bool, true
lives: int[1,9], 3
speed: float[0.25,3.0], 1.0
player_name: str, "Loaf"
difficulty: options[easy, normal, hard], normal
reset_stats: action, "Reset Everything"

Use the Mods menu, or inspect and change values from the console:

mods.config my_mod
mods.config.get my_mod difficulty
mods.config.set my_mod difficulty hard
mods.config.action my_mod reset_stats

Storage and bindings are different

storage.cfg is mod-owned persistent data, not a user options file. binds.cfg holds named input overrides. Use the Mods menu or binds.* console commands for bindings, and let the mod’s storage API manage storage.

If a value is invalid

Check mods/modframework.log. Parsers either fall back, clamp where documented, or reject the setting; they do not make every string meaningful. Restore a known valid value, then restart or use the feature’s live command. For example, music.output_rate 48000 validates, applies, and persists a mixer rate.
