Getting started

Console basics

The in-game console is the quickest way to inspect Yule, manage mods, and collect useful diagnostics without editing files.

Open and edit

Press backtick (`) to open or close the console. Esc, exit, and quit also close it.

KeyAction
EnterRun the current line.
Up / DownBrowse persistent command history.
TabComplete commands and supported arguments such as mod IDs and config keys.
Page Up / Page Down or wheelScroll output.
Ctrl+LClear displayed output.
Ctrl+CCopy input, or all console output when input is empty.
Ctrl+V or right clickPaste into the input line.

Discover commands

help
help mods
commands
find error

help is the authoritative runtime list. find searches lines already printed in the console. Command history is saved to mods/console_history.txt.

Direct ggpo.net host/join is a diagnostic protocol, not normal matchmaking. It requires the same one-shot 64-hex shared key on both machines: copy it, run ggpo.net key, and the framework clears the clipboard after reading it.

Input and arbitrary Lua

input.show [player] *
input.override <player> <mask> [frames] [replace] *
input.clear <player> *
lua <code>                       alias: eval *
lua.mod <id> <code>              alias: eval.mod *
lua.file <path> *

Commands marked * require dev on. The current runtime’s help output remains authoritative if a development build adds or removes a command.

Manage mods

mods.find speed
mods.info speedhack
mods.disable speedhack
mods.enable speedhack
mods.config speedhack
mods.config.set speedhack speed 1.5
reload.mods

Disabling a mod also disables enabled dependents that require it. Enabling succeeds only when dependencies and conflicts permit. A reload recreates mod runtimes, so unsaved Lua state is lost; persistent values belong in the storage API.

Lua execution

lua return 2 + 2
lua.mod options_demo return config.get("difficulty")
lua.file mods\my_mod\test.lua

lua.mod evaluates inside the named mod’s environment. Treat downloaded snippets like code: read them before running them.

Developer mode

Some invasive commands stay hidden until dev on. They are for controlled testing and may alter timing, input, game state, or rollback diagnostics. Turn developer mode back off when finished:

dev on
# run the documented test
dev off
Do not experiment with state-changing commands in an online match. Online code guards several unsafe paths, but developer tools are not a substitute for matched content and supported matchmaking.

Share useful output

Reproduce the problem, run the smallest relevant diagnostic, then use console.copy output. Pair it with the matching section of mods/modframework.log. Review copied text before posting it; diagnostics are designed to omit secrets, but unrelated Lua mods may print their own data.
