Getting started

Installation

The supported installer keeps the original SDL library, installs the framework as a proxy, and records what it owns so it can update or uninstall safely.

Requirements

  • Windows, or Linux with Wine, and a working Windows copy of eggnoggplus.exe.
  • The Windows or Linux/Wine Yule installer ZIP for the release you want to install.
  • Internet access while the installer retrieves and verifies release files.
  • Permission to write to the chosen game folder and to register optional shortcuts and yule:// links.
Before changing a valued copy: close every Eggnogg+ process and keep a clean backup of the original game folder. Do not install over a half-repaired DLL set.

Install

  1. Extract the complete Windows installer ZIP. Do not run the scripts from inside the ZIP preview.
  2. Run INSTALL.bat. The script first looks beside itself and in a previous install receipt. If it cannot find the game, it asks you to locate eggnoggplus.exe.
  3. Review the detected folder. Follow the prompts for the install location, shortcuts, and Steam integration. You can decline optional integration without disabling the framework.
  4. Let verification finish. On a vanilla copy, the installer renames the original SDL2.dll to SDL2_real.dll, then installs the verified proxy and its required runtime files.
  5. Launch eggnoggplus.exe. The updater helper is not a launcher; the game executable remains the normal entry point.

Linux with Wine

Extract the Linux/Wine installer ZIP, install Wine plus python3, sha256sum, curl or wget, and xdg-mime, then run bash install-linux.sh. Yule still targets the Windows game; the Linux installer copies it to ~/.local/share/yule/EGGNOGG+ by default and launches it through Wine.

The generated desktop entry and wrapper use one recorded Wine prefix for ordinary launches and yule:// links. That includes Greggnogg preview links and existing-instance forwarding. Pass --wine-prefix /path/to/prefix for a non-default prefix or --skip-protocol to omit desktop integration.

bash install-linux.sh --game-path /path/to/eggnoggplus.exe
bash install-linux.sh --uninstall

Verify the install

A healthy root contains these roles:

File or folderPurpose
eggnoggplus.exeThe game and only normal launch target.
SDL2.dllThe Yule proxy loaded by the game.
SDL2_real.dllThe preserved original SDL library that the proxy forwards to.
lua51.dll and MinGW runtime DLLsRuntime dependencies used by the framework.
YuleUpdater.exeA one-shot helper used only when replacing files mapped by a running game.
mods/Framework configuration, installed mods, logs, and runtime data.

After one launch, check mods/modframework.log. It should show framework and mod initialization rather than a missing-original-SDL error.

Updates

The framework checks its configured HTTPS channel after rendering begins, so a failed check does not block startup. Open Options → Mods → Framework to see the version and update state or change automatic updates. When a verified update is ready, return to a safe menu. The game starts YuleUpdater.exe, closes normally, swaps the complete verified set, and relaunches.

Do not launch the updater helper yourself. It expects a staged, journaled transaction and an exact game process handoff.

Uninstall safely

  1. Close Eggnogg+ and the update helper.
  2. On Windows, run UNINSTALL.bat. On Linux, run bash UNINSTALL-LINUX.sh.
  3. Confirm the recorded target. The uninstaller removes installer-owned integration and restores the original SDL2.dll from SDL2_real.dll.

If the framework proxy exists but SDL2_real.dll is missing, the uninstaller deliberately stops. Restore an original SDL DLL from a clean copy as SDL2_real.dll, then retry. Guessing or deleting the proxy would leave the game unbootable.

Why not copy only SDL2.dll?

The proxy depends on the original SDL library and additional runtime DLLs. A current release may also add or update supporting files. Use the release installer or a complete release payload; copying one DLL is a common cause of “code execution cannot proceed” dialogs.
