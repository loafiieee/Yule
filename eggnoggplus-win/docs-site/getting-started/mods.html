Getting started

Mods basics

Every mod is a folder under mods/ with a strict JSON manifest and a Lua entry file. Each mod receives its own environment and framework API.

Install a mod

  1. Read the mod’s source or obtain it from someone you trust.
  2. Extract its folder directly under mods/. The manifest should be at mods/<folder>/mod.json, not inside another duplicate folder.
  3. Launch the game or run reload.mods.
  4. Open Options → Mods or run mods.list to confirm discovery.
  5. If it did not load, inspect mods/modframework.log for its mod ID.

Folder names beginning with _ are ignored by the loader. Moving a mod to a name such as _disabled_example is a simple closed-game disable method.

Make the smallest mod

Create mods/hello_yule/mod.json:

{
  "id": "hello_yule",
  "name": "Hello Yule",
  "version": "1.0.0",
  "author": "you",
  "description": "My first Yule mod",
  "api_version": 1,
  "entry": "main.lua"
}

Then create mods/hello_yule/main.lua:

mod.on_load(function()
  mod.log("Hello from " .. mod.name)
end)

mod.on_unload(function()
  mod.log("Goodbye")
end)

Run reload.mods, then log.tail 20. The manifest’s id is the stable identifier used by logs, dependencies, console commands, and interop.

Manifest essentials

FieldPurpose
id, name, version, author, entryRequired identity and Lua entry point.
api_versionFramework API target. A mismatch is rejected unless explicitly overridden.
configOptional line-based settings file shown in Options → Mods.
storage, bindsOptional persistent-data and named-binding paths; each has a default.
depends, optional_depsHard and soft dependency specifications with version ranges.
conflicts, load_before, load_after, priorityCompatibility and deterministic load-order controls.

The parser reads the full file as strict JSON and validates field types. JSON does not allow comments or trailing commas.

Choose the right callback

mod.on_load(function() end)     -- runtime created
mod.on_unload(function() end)   -- disable, reload, or shutdown
mod.on_frame(function() end)    -- once per rendered frame
mod.on_tick(function() end)     -- once per gameplay update
mod.on_event(function(event)
  return false                 -- true consumes the SDL event
end)

Use on_frame for overlays and presentation. Use on_tick for deterministic gameplay logic. Input events and the synthetic delta_time event can be consumed or modified, but doing so may classify the mod as gameplay-affecting.

Add options

Add "config": "config.cfg" to the manifest, then create:

enabled: bool, true
message: str, "Hello"
size: float[0.5,3.0], 1.0
style: options[plain, loud, quiet], plain

Read it from Lua:

local enabled = config.get("enabled", true)
config.set("message", "Updated")

Online safety

The framework evaluates mod capabilities and suspends gameplay-affecting mods during online rollback. Cosmetic behavior must stay presentation-only. Do not depend on unsynchronized file I/O, wall-clock time, or global randomness for gameplay. Both peers also need matching custom map/content fingerprints.
