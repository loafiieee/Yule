Getting started

Troubleshooting

Start with the first failing boundary: Windows loading the game, Yule starting, one mod loading, a network route establishing, or the updater committing a verified set.

Collect useful evidence

  1. Note the exact action and the first error, not only the final symptom.
  2. Record whether vanilla, an older Yule release, or another machine behaves differently.
  3. Open mods/modframework.log and find the matching timestamp.
  4. If the in-game console works, run log.tail 40 and a subsystem diagnostic.
  5. Copy output with console.copy output and remove any unrelated personal data a third-party mod printed.

Windows will not start the game

“X.dll was not found” dialogs

This normally means an incomplete framework copy or an executable launched without its local runtime set. Do not download random DLLs from DLL websites.

  • Verify SDL2.dll, SDL2_real.dll, lua51.dll, libgcc_s_dw2-1.dll, and libwinpthread-1.dll are beside eggnoggplus.exe.
  • Use the complete installer package rather than copying only the framework proxy.
  • Launch eggnoggplus.exe, not a test executable or update helper.

Proxy exists but original SDL is missing

The Yule SDL2.dll forwards the original SDL interface to SDL2_real.dll. Restore the original DLL from a clean copy under that exact name, or let the supported installer repair the complete set.

The game starts, but Yule seems absent

  • Confirm the running executable is from the folder you inspected. Shortcuts can point at another copy.
  • Check that SDL2.dll is the framework proxy rather than the original.
  • Look for mods/modframework.log beside that executable.
  • Press backtick and try framework.api. The separate log window may simply be disabled.

A mod will not load

Log message or symptomCheck
Manifest parse/type errorUse strict JSON: quoted keys and strings, no comments, no trailing comma, and the required fields.
API mismatchUpdate the mod for the current API. Avoid allow_api_mismatch for released mods.
Missing dependencyInstall and enable a compatible version of the named mod.
Conflict or load cycleInspect mods.info <id> and adjust manifests rather than forcing load order at runtime.
Lua file/line errorOpen the named file and line. Fix the first error, then run reload.mods.
Folder never discoveredPut mod.json one folder below mods/ and remove a leading underscore from the folder name.

Online connection fails

Before queuing, run:

online.troubleshoot

Leave the console open for up to five seconds. The command tests TCP control and UDP rendezvous against the server in mods/online_hub.cfg, then reports which Windows adapter routes to it. VPN detection is heuristic: an active Radmin, tunnel, or overlay adapter may be noted without being the route used for the server.

  • TCP fails: verify the server hostname/port, DNS, service status, firewall, and HTTPS/TCP filtering.
  • TCP passes but UDP fails: check Windows Firewall, router/security filtering, and VPN kill-switch or split-tunnel rules.
  • Both pass but a peer match stalls: queue with another client on the same build, then run net.diag during the failure. Retain both client logs and server logs.
  • CGNAT: a private LAN address alone does not prove it. Compare the router WAN IPv4 with the public address observed by the server.
Version isolation is valuable. If release 1.0 works and the current build fails on the same machine and network, report that exact A/B result. It sharply narrows the fault to framework protocol or state changes.

Updater or recovery problem

Read mods/updater.log. If recovery says a committed cleanup is incomplete, retain the journal, .old, .update-recovery, and mods/update_staging evidence. Do not delete pieces until the installed and backup hashes are understood.

  • Close every process running the same installed eggnoggplus.exe.
  • Verify the folder is writable and security software is not holding a payload.
  • Use a complete release package for repair. Do not advertise a release before every manifest payload is publicly available and hash-correct.
  • Never test destructive recovery against your only copy.

Crash with no dump

A failure can happen before Yule installs its crash handling or in a loader/runtime boundary that cannot safely write. Capture the Windows event details, the last modframework.log lines, exact launch method, current DLL hashes, and whether a clean or previous-release folder starts. Disable third-party overlays and mods one group at a time only after preserving the original evidence.
