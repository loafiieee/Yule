Create custom maps

A map package is a folder containing strict room text and metadata. V1 uses native glyphs. V2 adds a genuine map-wide tileset, symbolic tile definitions, and an optional deterministic map.lua.

1. Choose the format

NeedUse
Vanilla glyph behavior, custom room order/colors/ambienceeggnogg-map/v1
Reskin every normal map tile from one sheetV2 with tileset.native_layout=true
New symbolic sprites/collision/animationV2 tileset.tiles[]
Programmable springs, fans, or bounded contact logicV2 plus map.lua

Both versions retain the engine's fixed 33×12 source rooms, at most nine source rooms, and center-out mirroring. Final visible rooms are 2 × source rooms − 1.

2. Make the package

maps/
  mossy_caverns/
    data.json
    data.map
    tiles.png   # V2, optional
    map.lua     # V2, optional

Folders beginning with _ are ignored. Package files must be direct non-reparse files. data.json and data.map are each limited to 4 MiB; map Lua is limited to 256 KiB.

3. Draw source rooms

; comments are allowed outside rows
[center]
"@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@"
"@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@"
"                                 "
"       #                 #       "
"                                 "
"   *                         *   "
"@@@@@@                     @@@@@@"
"@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@"
"@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@"
"@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@"
"@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@"
"@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@"

Every room has exactly 12 quoted rows and every row contains exactly 33 bytes. Spaces inside quotes matter. List source rooms from center outward; the engine mirrors every room after the first. Use only the native glyph set in V1. V2 may bind any printable ASCII byte to a custom tile.

Some native glyphs expand into neighboring cells. G is 3×3; L, N, and Y are 2×3; tentacles and waterfalls also have nonlocal behavior. Check the glyph table before placing them at an edge.

4. Add metadata and rules

{
  "format": "eggnogg-map/v1",
  "id": "mossy_caverns",
  "name": "Mossy Caverns",
  "author": "you",
  "description": "A compact duel",
  "sort_order": 10,
  "rules": {
    "mode": "swords",
    "round_end_rooms": "inner_only",
    "score_target": null,
    "armed_respawn_limit": 4
  },
  "layout": {
    "kind": "mirrored_source_rooms",
    "room_format": "vanilla_33x12",
    "order": ["center", "outer"]
  },
  "defaults": {"room": {"ambient": "none"}},
  "rooms": {
    "center": {"ambient": "dust"},
    "outer": {"ambient": "bubbles"}
  }
}

Room appearance banks are primary and mirror. Each may override fg1, fg2, bg1, bg2, water, water_hi, special, and special2 with RGB triples in 0..1. Appearance is visual; actual water and hazards still come from glyphs.

5. Give the whole map a tileset

{
  "format": "eggnogg-map/v2",
  "...": "...",
  "tileset": {
    "sprite_sheet": "tiles.png",
    "cell_w": 16,
    "cell_h": 16,
    "padding": 0,
    "native_layout": true,
    "tiles": []
  }
}

This is map-level customization, not per-tile duplication. With native_layout=true, the first 128 row-major cells replace the native data/tiles.png prefix for all ordinary unlisted glyphs. Extra cells are available to explicit definitions. The image is not required to be 128×256 or to use a fixed grid shape: it only needs a valid declared grid containing at least 128 cells.

With native_layout=false, the top-level sheet is simply inherited by each explicit tile and unlisted glyphs keep native visuals. External sheets may be 1×1 through 4096×4096, up to 64 MiB and 8,192 cells. The runtime computes SHA-256 automatically; asset_sha256 is an optional pin, not author homework.

6. Define simple symbolic tiles

"tiles": [
  {
    "id": "moss_floor",
    "symbol": "$",
    "name": "Moss Floor",
    "collision": "solid",
    "sprite_index": 128,
    "frame_count": 4,
    "frame_ticks": 6,
    "animation": "ping_pong",
    "native_visual": "underlay",
    "random_phase": true,
    "tint": [0.4, 1, 0.5, 1]
  }
]

Collision presets are solid, pass_through, and hazard; they map to verified native behavior. For collision:"native", provide a safe single-cell native_glyph unless the symbol itself is safe. Use native_visual:"underlay" when a prop should draw over ordinary terrain rather than replacing the surface.

Definitions can choose an exceptional sprite_sheet, animation, batch layer 0/1, mirror, deterministic phase, offset, scale, rotation, and tint. Keep unique behavior out of JSON: declarative force_x/y remains for small cases, but map Lua is clearer and more programmable.

7. Program contact behavior

map.sensor(">", {
  tile_box={left=0, top=0, right=1, bottom=.375},
  object_box={left=-.375, top=0, right=.375, bottom=.375},
  objects={"alive_player", "sword"},
  contact_scope="binding",
})

map.on_enter(">", function(object, tile)
  local launch = object.kind == "player" and -4 or -2.8
  object.vy = launch
  object:set_velocity_limits({min_vy=launch}, 8)
  tile:set_sprite(129, 16, {offset_y=8})
end)

Use a sensor to tune the contact region and object profiles. Binding scope makes adjacent tiles behave as one pad. Temporary sprite offsets can lift an active frame without moving the collision tile. Persistent behavior state belongs in map.state; randomness must use map.random.

Read the map Lua reference for all geometry, lifecycle, rollback, and sandbox limits.

8. Understand reload and fallback

The scanner validates a complete package before atomically replacing the live registry. Invalid edits keep the last valid generation. New definitions remain unresolved safely if the atlas cannot rebuild; native fallback collision/rendering runs instead.

JSON/art changes can rebuild live outside online rollback. A generated map pins its room/script generation; script source changes are used on the next generation. External PNG bytes and script bytes automatically affect the stable online map key, so two peers with different assets/scripts will not silently use the same package identity.

9. Validate and test

powershell -NoProfile -ExecutionPolicy Bypass -File tests/run_v2_map_test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/run_map_script_test.ps1
  1. Start the game and select the custom map in the normal picker.
  2. Check every native glyph, full-map atlas cell, explicit symbol, animation, layer, mirrored copy, palette, and missing-asset fallback.
  3. For scripts, test each object profile, sensor edge and seam, enter/contact/leave, death/respawn, temporary sprite expiry, and room reset.
  4. Edit tint and save; confirm atomic hot reload. Introduce invalid Lua; confirm the prior valid package remains.
  5. Run two online clients with the exact package. Confirm matching map/content fingerprints and rollback behavior.
  6. Return to a vanilla map and verify the native atlas/palette are restored.

The checked-in maps/v2_symbolic_demo is the acceptance fixture for full-map art, custom tiles, spring/fan logic, fallback, mirroring, and hot reload.
