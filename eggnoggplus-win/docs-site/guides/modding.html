Build a Lua mod

Mods live in one folder under mods/, declare metadata in strict JSON, and run Lua through the framework proxy. This guide takes a small mod from an empty directory to a package players can configure and debug.

1. Create the smallest working package

mods/
  hello_yule/
    mod.json
    main.lua
{
  "id": "hello_yule",
  "name": "Hello Yule",
  "version": "1.0.0",
  "author": "you",
  "description": "A tiny overlay example",
  "api_version": 1,
  "api_revision": 1,
  "api_requires": ["input.bindings", "ui.native"],
  "entry": "main.lua",
  "config": "config.cfg",
  "storage": "storage.cfg",
  "binds": "binds.cfg"
}
mod.on_load(function()
  mod.log("loaded")
  mod.input.bind("toggle", "h", "Toggle greeting")
end)

local visible = true
mod.on_frame(function()
  if mod.input.pressed("toggle") then visible = not visible end
  if visible then
    mod.ui.begin_overlay()
    mod.ui.text_at("Hello from Lua", 32, 32, 1, 1, .9, .4)
    mod.ui.end_overlay()
  end
end)

Start the game and inspect mods/modframework.log. Folders beginning with _ are ignored, which is useful for templates and disabled copies.

2. Describe dependencies and load order

Required manifest fields are id, name, version, author, and entry. Set the compatible api_version major for released mods, the minimum additive api_revision you tested, and only the api_requires capabilities without which the package cannot start. Compatibility failures happen before entry-script side effects.

{
  "priority": 10,
  "depends": ["shared_lib@>=1.2.0 <2.0.0"],
  "optional_deps": ["ui_pack@^1.3.0"],
  "load_after": ["ui_pack"],
  "load_before": ["late_overlay"],
  "conflicts": ["incompatible_mod"]
}

Supported comparisons are =, ==, !=, >, >=, <, <=, ^, and ~. Hard dependencies block a load; optional dependencies only influence ordering. Use mod.api.has for optional feature branches. Use allow_api_mismatch only during deliberate local compatibility work, never in a release.

3. Add in-game settings, binds, and storage

# config.cfg
enabled: bool, true
lives: int[1,9], 3
gravity: float[0.2,2.5], 1.0
player_name: str, "Loaf"
difficulty: options[easy, normal, hard], normal
reset_stats: action, "Reset Everything"

These rows appear in Options → Mods. Boolean toggles, bounded numbers, editable strings, option cycles, and action buttons are built in. Read them with config.get, update them with config.set, and register action handlers with config.on_action.

local runs = storage.get("runs", 0)
storage.set("runs", runs + 1)

if storage.schema() < 2 then
  assert(storage.migrate(2, function(from, target)
    if from < 1 then storage.set("coins", 0) end
    if from < 2 then storage.set("xp", 0) end
    return true
  end))
end

Register input names with mod.input.bind. Players can capture keys in the Mods options screen; you can also inspect them through binds.list in the console.

4. Keep the mod maintainable

mods/my_mod/
  mod.json
  main.lua
  config.cfg
  lib/
    model.lua
    view.lua
  assets/
    icons.png
    click.wav
  • Load files with mod.dofile("lib/model.lua") so they share the mod's isolated environment.
  • Put persistent data in storage, not arbitrary files, when the value fits bool/number/string.
  • Expose small versioned services through mod.interop.provide; prefix the namespace with your mod id.
  • Keep on_frame presentation-only when possible. Use on_tick for deterministic gameplay work.
  • Preload reusable assets/audio instead of allocating unique work every frame.

5. Draw overlays or a complete screen

For a HUD, wrap draw calls in begin_overlay/end_overlay so the engine flushes its sprite batch around your layer. Use measured/wrapped text and readable_scale instead of hard-coding around one window size.

For a full screen, use mod.ui.define_state with enter/update/render/event/leave callbacks. Framework states provide the native mouse cursor by default and can disable or customize it. Engine-backed native buttons support sword selectors and controller navigation; the immediate-mode widgets are better for fully custom layouts.

Pointer-based vanilla button edits are fixed-address integration. Re-apply changes on frame/state recreation and test against the supported executable.

6. Load sprites, fonts, textures, and sound

  • Mod sprites: mod.assets.load_spritesheet, then sprite_id and mod.ui.draw_sprite. Batch several sheets to rebuild the native atlas once.
  • Font icons: allocate or register exact 8×8 PNG glyphs with mod.font.
  • Texture packs: use mod.texture for exact-dimension replacements of native data/*.png atlases.
  • Audio files: play_sfx and play_music; file-format support depends on the installed mixer.
  • Procedural sound: bounded bytebeat/floatbeat is mixed through the game's existing device and does not require SDL2_mixer.dll. See audio & music.

7. Debug the mod

  1. Open the console with backtick.
  2. Run mods.info hello_yule, mods.trace hello_yule on, and log.tail 60.
  3. Inspect live values with lua.mod hello_yule return config.get("enabled").
  4. Use reload.mods after code edits and reload.assets after art edits.
  5. Use mods.disable/mods.enable to verify unload/load cleanup.

Do not retain engine button pointers or volatile atlas base ids indefinitely. Query again after state/atlas rebuilds. Handle nil,error from asset operations when graphics are not ready.

8. Design for online safety

Gameplay-affecting packages are automatically suspended for matchmaking, countdown, gameplay, and cleanup. A package is classified after tick registration, bot/game mode registration, content transaction work, delta-time changes, or a mutating mod.game call.

If your mod contains both a gameplay feature and a useful HUD, split them. A read-only/cosmetic package can keep drawing online; a mixed package is suspended as one unit. Never treat framework suspension as anti-cheat—it protects the supported runtime path, not a malicious native client.

9. Package and test

  • Use a stable lowercase id and semantic version.
  • Set the compatible api_version, minimum api_revision, and required api_requires; run framework.api to inspect the build.
  • Remove secrets, generated logs, console history, and user storage from the archive.
  • Test clean install, enable/disable, hot reload, missing optional dependency, dependency mismatch, and configuration migration.
  • Test every supported window size/input method and confirm unload stops owned audio and removes owned UI/content.

Use the complete Lua API reference while implementing and the testing guide before publishing.
