Deploy the online server

The dependency-free Node service uses newline-delimited JSON over TCP for accounts/social/matchmaking and UDP for rendezvous plus bounded relay. Run one supervised process with both protocols on the public port.

Server responsibilities

The bundled prototype handles accounts, password verification, public Elo/private MMR, casual and widening-range competitive queues, friends, requests, block/mute state, five-minute map-aware challenges, private rematches, shared-map selection, P2P candidate signaling, relay, match lifecycle, result confirmation, and optional outbound Discord LFG.

It does not run gameplay simulation, validate rollback state, or make one player authoritative. Clients exchange authenticated deterministic inputs.

1. Install and check

cd /srv/yule/eggnoggplus-win/online_server
node --version              # Node 18 or newer
npm run check
npm test

No runtime npm dependencies are required, but keep the matching server.js, admin_server.js, discord_lfg_bot.js, lfg_redirect.js, and package.json together.

3. Run under systemd

[Unit]
Description=Eggnogg Online Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=loaf
Group=loaf
WorkingDirectory=/home/loaf/Yule/eggnoggplus-win/online_server
Environment=HOST=0.0.0.0
Environment=PORT=47778
Environment=ADMIN_HOST=127.0.0.1
Environment=ADMIN_PORT=47779
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=5
StandardOutput=append:/home/loaf/Yule/eggnoggplus-win/online_server/server.log
StandardError=append:/home/loaf/Yule/eggnoggplus-win/online_server/server.err.log

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now eggnogg
sudo systemctl status eggnogg --no-pager

Do not start a second nohup node server.js beside a supervised instance; it will only contend for the same TCP/UDP port.

4. Open TCP and UDP

Allow and forward the public server port for both protocols. On UFW:

sudo ufw allow 47778/tcp
sudo ufw allow 47778/udp
sudo ss -ltnp | grep 47778
sudo ss -lunp | grep 47778

A DNS record is not enough; the router/security group must direct both protocols to the host, and the Node process must own both sockets.

Optional LAN administration UI

The separate maintenance listener provides searchable account status, password reset, ban/unban, force-disconnect, rating reset, and queue/match counts. It is not exposed on the public game port and intentionally has no admin password: private-LAN access is the authorization boundary. Set ADMIN_ENABLED=0 to turn it off.

Keep ADMIN_HOST=127.0.0.1 for same-machine or SSH-tunnel access. For direct LAN use, bind the machine's exact private address, for example ADMIN_HOST=192.168.1.50, then allow only the administrator subnet:

sudo systemctl edit eggnogg

# Add this drop-in:
[Service]
Environment=ADMIN_HOST=192.168.1.50
Environment=ADMIN_PORT=47779

sudo systemctl daemon-reload
sudo systemctl restart eggnogg
sudo ss -ltnp | grep 47779

The listener is part of server.js. Do not run node admin_server.js separately; it has no standalone maintenance API.

sudo ufw allow from 192.168.1.0/24 to any port 47779 proto tcp
Never port-forward 47779 or allow it from Anywhere. Wildcard/public binds and non-private client addresses fail closed by default. ADMIN_ALLOW_WILDCARD=1 is an unsafe emergency override. Plain HTTP belongs only on a trusted isolated LAN; use an SSH tunnel or authenticated TLS reverse proxy across an untrusted network.

The first private-client visit automatically receives a random, IP-bound, HttpOnly, SameSite=Strict session, capped and expiring after eight hours. The session owns a CSRF token and every state change is POST-only, so an unrelated webpage cannot silently submit an action. Set ADMIN_COOKIE_SECURE=1 when the browser always reaches the UI through HTTPS.

Client admission and protocol compatibility

The client map_manifest reports an informational framework_version, strict integer control/match/P2P protocol versions, and deterministic build_id, game_exe_id, and framework_dll_id fingerprints. The current client requires the server to advertise cap_client_build_gate: 1. The server rejects missing, malformed, or old values before queue/challenge entry and pairs only exact 3/3/17 clients whose complete build fingerprint tuples match. P2P v16/v17 cannot interoperate because their authentication-key domain and packet layout differ.

Use the server log to confirm deployment: registration should contain [maps] ... build=... exe=... dll=... protocols=3/3/17; match creation should record the checked build and p2p=17. Release labels help diagnosis but are not the admission gate.

5. Run the deployment preflight

python check_deployment.py
python check_deployment.py 127.0.0.1 47778
python ../tests/online_server_match_protocol_test.py
python ../tests/discord_lfg_server_static_test.py
npm test

The probe checks the flat server_info response and an actual UDP udp_ping/udp_pong. Current deployment must advertise control 3, match 3, P2P 17, packet auth, social controls, private rematch, and relay. Replacing source without restarting does not update the listening process.

If TCP matchmaking succeeds but server logs never show received P2P probes, trace UDP from public ingress to the Node socket. If direct traversal fails, confirm both clients receive one relay generation and that the server logs relay activation.

6. Update application files safely

cd /home/loaf/Yule/eggnoggplus-win/online_server
chmod +x update_server.sh
./update_server.sh

The script clones the configured repository/ref into a temporary directory, runs server checks before downtime, stops the service, swaps only application files, restarts, waits for readiness, and probes TCP plus UDP. If startup/protocol validation fails, it restores the previous application files.

If an older deployment reports clone did not contain online_server/server.js, its updater predates nested-layout discovery. Replace only that script, then rerun it:

cd /home/loaf/Yule
git fetch origin main
git show origin/main:eggnoggplus-win/online_server/update_server.sh \
  > /tmp/yule-update-server.sh
bash -n /tmp/yule-update-server.sh
install -m 0755 /tmp/yule-update-server.sh \
  eggnoggplus-win/online_server/update_server.sh
cd eggnoggplus-win/online_server
./update_server.sh

This bootstrap changes only update_server.sh. The replacement locates a unique project root using the server entry point, package metadata, and test directory, regardless of whether the repository is flat or nested.

Useful overrides: YULE_REPOSITORY_URL, YULE_REPOSITORY_REF, YULE_SERVICE_NAME, YULE_SERVER_PORT, YULE_TARGET_ROOT, and YULE_READINESS_TIMEOUT_SECONDS.

Run the updater from the actual online_server checkout. A clone with no complete online-server project—or multiple ambiguous copies—is correctly rejected.

Persistent data that updates must preserve

  • users.json and ratings.json
  • server_secret.key and any external environment/secret file
  • server logs and diagnostics
  • PID/socket files, caches, and node_modules

Before first production update, record file hashes and backup the complete persistent set. The updater intentionally never stages it. Test rollback in a disposable deployment before depending on it remotely.

Operational checklist

  • Drain or announce downtime before changing a protocol-breaking server.
  • Run syntax/tests locally, deploy payload, restart the supervised process, then run public TCP+UDP preflight.
  • Watch memory, control disconnects, matchmaking latency, UDP probe/relay counters, result conflicts, disk errors, and JSON corruption.
  • Back up persistent JSON and secret material securely; rehearse restoration and key rotation.
  • Never log credentials, session/P2P tokens, or full environment output.
  • Verify the passwordless admin listener is reachable only from the intended private LAN and absent from public port scans.
  • Put a future authenticated TLS boundary in front of control traffic before treating public passwords/ranked play as production-secure.
