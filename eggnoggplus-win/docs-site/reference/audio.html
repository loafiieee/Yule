Audio and music

The framework supports native synth effects, mod-owned files, bounded bytebeat/floatbeat PCM, the native postfix playlist, and explicitly marked Dollchan-compatible JavaScript tracks.

Mod audio API

mod.audio.play_sfx("assets/click.wav", {volume=.8})
mod.audio.play_sfx("pip", {pitch=1.2, duration=80})
mod.audio.play_music("assets/loop.ogg", {loops=-1})
mod.audio.set_sfx_volume(.8)
mod.audio.set_music_volume(.6)
mod.audio.stop_music()

File SFX options are volume, loops, and maximum ticks in milliseconds. Music is one global channel and ownership is tracked; one mod cannot stop another mod's current music. File codecs depend on the installed SDL2_mixer.

Built-in ids: pip, noise, thump, shred, fm, ringmod, warble, creepy, pulse, and sword_ching/ching.

Bounded bytebeat and floatbeat

local ok, info = mod.audio.play_bytebeat(
  "t*((t>>12|t>>8)&63&t>>4)",
  {mode="bytebeat", sample_rate=8000, duration=8, fade_ms=8,
   gain=.7, volume=.8, loops=0, ticks=-1}
)

bytebeat_info(expression,opts) validates without rendering or initializing audio. stop_sfx() stops this mod's voices; clear_generated() also frees its generated cache; status() reports backend, voices, chunks, bytes, limits, and volume.

Generated PCM does not need SDL2_mixer.dll. It uses a bounded native voice pool in Eggnogg's already-open callback. Exact expression/options pairs reuse an owned cache entry.

Bounded expression language

Variables: t, sr/sampleRate/sample_rate, time/seconds, pi/PI/Math.PI, and e/E.

Operators follow JS-like numeric precedence: unary + - ~ !; power **; arithmetic; shifts; comparison/equality; bitwise & ^ |; short-circuit && ||; and conditional ?:. Functions (with optional Math.) include trig, abs/floor/ceil/round/trunc/int/fract/sign, sqrt/log/exp/pow, min/max/clamp, and deterministic noise(value).

This is not JavaScript: no strings, arrays, assignment, properties beyond fixed Math aliases, callbacks, allocation, filesystem, network, global state, or ambient random source.

Native playlist files

The playlist is contiguous: data/tune.txt, data/tune1.txt, and so on. A numbering gap hides later tracks until it is filled. Existing unmarked files use Eggnogg's native postfix stack language.

A bounded bytebeat track uses a marker followed by one expression:

$"Track title"
( yule:bytebeat sample_rate=44100 volume=0.25 )
t*((t>>12|t>>8)&63&t>>4)

Bounded playlist formulas allow more evaluation work per source second than short mod SFX but keep the same deliberately small expression surface.

Dollchan-compatible JavaScript tracks

$"Track title"
( yule:bytebeat engine=dollchan mode=bytebeat sample_rate=44100 volume=0.25 )
M=T=>(/* original Dollchan expression */),M(t/5000)

Modes: bytebeat, signed-bytebeat, floatbeat, and funcbeat. Scalar results are mono; [left,right] is stereo. Short Math names, assignment, arrow functions, arrays, and private random() follow the Dollchan execution shape. Funcbeat receives (time,sampleRate).

The isolated runtime uses system Chakra where supported and a vendored core-only QuickJS-NG fallback. It receives no DOM, host objects, modules, filesystem, process, shell, or network. A producer thread fills eight 4,096-frame stereo blocks before playback; JavaScript never runs in the real-time audio callback.

Unmarked general JavaScript is intentionally rejected because rate and playback mode would be ambiguous.

Source sample rate versus mixer output rate

sample_rate controls the formula's t, tempo, and pitch. output_rate controls only the SDL device. They are independent.
  • sample_rate: 4,000..48,000 Hz, default 8,000.
  • Global music_output_rate: 8,000..192,000 Hz, normally 48,000 to avoid destructive downsampling of 32–48 kHz formulas.
  • A track may set output_rate=44100 in its marker without changing global configuration.

Changing output rate reopens the SDL mixer synchronously on the main thread but does not alter track tempo.

Commands and acceptance

music.status
music.scan
music.rescan
music.play 8
music.play random
music.output_rate
music.output_rate 48000

music.scan labels native-postfix, bounded-bytebeat, Dollchan JS, unsupported JS, and tracks hidden by numbering gaps. music.rescan discovers files added while the game runs.

For regressions, run tests/run_core_native_tests.ps1. Live-test tempo, stereo, output rate, hot reload, cache reuse, stop/clear ownership, long-track continuity, and compare Dollchan-marked tracks against the same source in Dollchan. A PCM producer underrun means the machine could not render a heavy formula in real time.
