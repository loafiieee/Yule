Configuration reference

The framework uses strict JSON only where structured schemas are needed and small line-based files for user-editable settings. Paths are rooted in the installed game directory after every normal or deep-link launch.

mod.json

{
  "id": "my_mod",
  "name": "My Mod",
  "version": "1.0.0",
  "author": "you",
  "description": "Optional text",
  "api_version": 1,
  "api_revision": 1,
  "api_requires": ["fs.pick_file"],
  "allow_api_mismatch": false,
  "entry": "main.lua",
  "config": "config.cfg",
  "storage": "storage.cfg",
  "binds": "binds.cfg",
  "priority": 10,
  "depends": ["shared@>=1.0 <2"],
  "optional_deps": ["ui_pack@^1.3"],
  "conflicts": ["other_mod"],
  "load_after": ["ui_pack"],
  "load_before": ["late_overlay"]
}
FieldRequired / contract
idRequired stable string, 1..63 chars. Content-compatible ids are stricter: ≤47 chars, letters/numbers/._-, no leading dot/hyphen.
name, authorRequired, 1..63 chars.
versionRequired, 1..31 chars; semantic version recommended.
entryRequired mod-relative Lua path, 1..127 chars.
descriptionOptional, up to 255 chars.
api_versionRecommended API major integer. A different major rejects before the entry script runs.
api_revisionOptional minimum additive revision, default 0. A newer requirement rejects on an older API-1 framework.
api_requiresOptional unique list of up to 32 stable lowercase capability ids. Every capability must be available before load.
allow_api_mismatchOptional boolean override for major, revision, or capability failures; unsafe for releases. Local environment override: LUNA_ALLOW_API_MISMATCH=1.
config, storage, bindsOptional relative paths, each ≤127 chars. Storage/binds default to the names above.
priorityInteger load-order tie breaker; higher loads earlier.
depends, optional_depsUp to 32 dependency strings, each ≤159 chars.
conflicts, load_before, load_afterUp to 32 mod ids per list.

Dependency forms: other, other@>=1.2 <2, or other>=1.2. Operators are = == != > >= < <= ^ ~. Invalid JSON/types produce a concrete log error rather than partial load.

API policy: a major is the compatibility boundary. Revisions only add contracts. Stable capability identifiers do not change meaning or disappear during a major. Deprecated functions remain for the rest of their major and document a replacement; ordinary removal waits for the next major. Use mod.api.has for optional behavior and api_requires only when the package cannot start without a feature.

Typed mod config grammar

# Comments begin with # or //
enabled: bool, true
lives: int[1,9], 3
gravity: float[0.2, 2.5], 1.0
player_name: str, "Loaf"
difficulty: options[easy, normal, hard], normal
reset_stats: action
reset_everything: action, "Reset Everything"
  • One row per setting: key: type, value.
  • int/float bounds are optional and inclusive in menu editing.
  • options[...] always resolves to one declared string. An invalid default falls back to the first option.
  • Quote strings containing spaces or commas.
  • Actions have no stored value; the optional quoted text is the label.

Menu behavior: bool toggles; number clicks increment; strings enter text edit (Enter saves, Esc cancels); options cycle left/right; actions call the registered handler. Lua surface: config.get, config.set, config.on_action, and config.path.

Storage and bind files

The storage API persists boolean, finite number, string, or nil/delete, with an integer schema version and transactional migration callback. Mods should not assume hand-edited line ordering. Call storage.save() when an immediate durable write matters.

Binding overrides are keyed by the stable ids passed to mod.input.bind. Supported names include keyboard tokens such as space, a, left, escape, and F1. Let the API/menu/console write binds.cfg; do not store transient down/edge state.

mods/modframework.cfg

KeyValues / behavior
show_log_console0|1; persisted visibility of the separate framework log console, default hidden.
main_menu_modeStable play-mode id such as play or online; unknown/unavailable registrations fall back safely.
auto_update0|1; missing means enabled.
update_channel_urlHTTPS release channel override; HTTP allowed only for localhost/127.0.0.1/::1 testing.
music_output_rate8,000..192,000 Hz SDL output rate, normally 48,000.
discord_presence0|1; local Discord Rich Presence toggle.
discord_application_idPublic 1..20 digit Discord snowflake; configurable live with discord.app.

Framework writers preserve unrelated lines/comments and use serialized atomic replacement. The internal persistence helper accepts keys 1..63 ASCII letters/digits/._- and values up to 4,096 bytes without CR/LF.

mods/online_hub.cfg

# Eggnogg+ built-in online hub config v2
username=loaf
remember_me=1
server_host=eggnogg.loafiieee.com
server_port=47778
local_port=0
challenge_notifications=1
match_hud=0
KeyContract
usernameLast canonical account name.
remember_me0|1. The password/token remains in Windows Credential Manager, never this file.
server_host, server_portControl/rendezvous target; port 1..65535. Settings UI presents one host:port.
local_port0 for Auto, otherwise 1..65535 requested local P2P UDP port. Retries may deliberately bind a fresh automatic port.
challenge_notifications0|1; visual challenge toast preference. Muted challenges still appear in the inbox.
match_hud0|1; default-off small active-match ping/input-delay/rollback overlay. Also controlled by ggpo.net hud.

Deleting or editing this file does not remove a remembered secret from Credential Manager; use the in-game Remember me flow to change that state.

Playlist marker keys

( yule:bytebeat engine=dollchan mode=bytebeat
  sample_rate=44100 output_rate=48000 volume=0.25 )
KeyValues
enginebounded (default) or dollchan.
modeBounded: bytebeat. Dollchan: bytebeat, signed-bytebeat, floatbeat, funcbeat.
sample_rate4,000..48,000 Hz, default 8,000; controls formula time/tempo/pitch.
output_rateOptional 8,000..192,000 track-specific mixer override.
volume0..1, default 0.25.

Online server environment

Core bind/data variables:

HOST=0.0.0.0
PORT=47778
UDP_HOST=0.0.0.0
UDP_PORT=47778
DB=/path/users.json
RATINGS=/path/ratings.json
SECRET_FILE=/path/server_secret.key
DEFAULT_ELO=1000
DEFAULT_MMR=1000
INPUT_DELAY=1

Lifecycle/match tuning includes REMATCH_TTL_MS, MATCH_REPORT_TIMEOUT_MS (legacy alias MATCH_SINGLE_REPORT_GRACE_MS), MATCH_SETUP_STALE_MS, MATCH_SWEEP_INTERVAL_MS, CLIENT_IDLE_TIMEOUT_MS, COMPETITIVE_BASE_RANGE, COMPETITIVE_RANGE_PER_SEC, and COMPETITIVE_MAX_RANGE. Transport: P2P_RELAY_ENABLED, RELAY_FINISH_GRACE_MS, and UDP_DIAG.

The optional passwordless maintenance listener uses ADMIN_HOST (default 127.0.0.1) and ADMIN_PORT (default 47779), and is disabled with ADMIN_ENABLED=0. Set the exact private LAN address for LAN access; wildcard/public binds fail closed unless the unsafe ADMIN_ALLOW_WILDCARD=1 override is explicit. Set ADMIN_COOKIE_SECURE=1 behind an HTTPS-only proxy.

Optional Discord LFG variables and safe secret-file setup are documented in Discord, LFG & deep links. The complete deployment sequence is in server deployment.

Editing and persistence rules

  • Close the game before hand-editing values whose in-memory owner may save later.
  • Keep credentials/tokens out of every config, manifest, log, screenshot, and release archive.
  • Do not repurpose a stable id/key after release; migrations depend on it.
  • Use framework UI/API writers where available so validation and atomic replacement apply.
  • Back up player-owned storage before schema migrations and server-owned JSON before deployment updates.
  • Never solve a release-version mismatch by changing only channel JSON; use the release procedure.
