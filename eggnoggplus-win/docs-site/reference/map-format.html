Custom map format

V1 defines engine-native rooms. V2 is backward-compatible and adds namespaced symbolic tiles, sprite sheets, deterministic map Lua, and independently sized source rooms through variable_cells.

Package and engine limits

maps/map_id/
  data.json
  data.map
  tiles.png   # V2 optional
  map.lua     # V2 optional
Source roomV1 and vanilla_33x12: exactly 33 columns × 12 rows. V2 variable_cells: independently sized 8–128 columns × 6–64 rows.
Source rooms1..9, ordered center outward
Final layoutCenter plus mirrored outer copies: 2n − 1 rooms
data.json / data.map4 MiB each
map.luaDirect non-reparse file, 256 KiB
Package safetyFolders beginning with _ ignored; map folder and package files may not be reparse points

V1 does not support variable room dimensions, asymmetric final layouts, custom glyph definitions, or room callbacks. V2 variable_cells supports per-room dimensions while retaining the mirrored source-room layout.

Two-dimensional room layouts. V2 room_graph maps support up to 17 placed room instances with validated horizontal, vertical, branched, looped, and one-way connections. Each node may override ambient, native_tileset, and opponent_spawn inside an overrides object without changing its reusable source room. A connection's optional players value is both, player1, player2, or go; its optional focus is go or crossing. These control who can traverse the opening and whether the GO player or whichever player crosses moves the active room. Falling through an allowed bottom opening reaches the connected room instead of triggering the native map-boundary death. Greggnogg's Full map view edits these choices and exports the same graph used by native traversal and online content identity. mirrored_source_rooms remains supported.

Player starts and respawn markers

Spawn markers are overlays stored separately from terrain. Greggnogg places them from the Spawn markers group in the normal tile catalog and shows them only while a spawn marker is selected.

"spawn": {
  "players": {
    "1": {"x": 4, "y": 10, "facing": "right"},
    "2": {"x": 28, "y": 10, "facing": "left"}
  },
  "markers": [
    {"x": 4, "y": 11, "kind": "allow_p1"},
    {"x": 28, "y": 11, "kind": "allow_p2"},
    {"x": 16, "y": 11, "kind": "deny"}
  ]
}

Coordinates identify the floor cell beneath the player. Marker kinds are deny, allow, allow_p1, and allow_p2. Any applicable allow marker enables whitelist mode for that player; otherwise native spawn search runs while excluding deny cells. Rooms accept at most 128 unique markers. Mirrored rooms mirror positions and facing, and online package identity includes all spawn metadata.

Room ambience and appearance

Ambience accepts integer 0..9 or: none (0), bugs, clouds, art, flies, drips, dust, bats, bubbles, and boil/fumes (9).

"appearance": {
  "primary": {
    "fg1": [1,1,1], "fg2": [1,1,1],
    "bg1": [0,0,0], "bg2": [0,0,0],
    "water": [0,.2,.4], "water_hi": [.5,.8,1],
    "special": [1,1,1], "special2": [1,1,1]
  },
  "mirror": {"bg1": [.1,0,.2]}
}

Each color is exactly three finite channels in 0..1. Per-room fields inherit field-by-field from defaults.room; omitted mirror values inherit the fully resolved primary bank. These values are presentation-only. Water placement/hazard behavior comes from data.map.

V2 custom particles and ambiances

V2 maps can declare reusable particle pictures in particles, combine them into named ambiances, and select a custom ambiance id through the ordinary room ambient field. Greggnogg exposes this through Edit particles beside the room selector.

{
  "particles": [{
    "id": "ember", "name": "Ember", "lifetime_ticks": 210,
    "fade_in_ticks": 12, "fade_out_ticks": 32,
    "visual": {"sprite_sheet": "builtin:misc", "sprite_index": 30,
      "frame_count": 1, "frame_ticks": 1,
      "tint": [1,.48,.16,.86], "end_tint": [.55,.08,.01,0],
      "scale_x": .55, "scale_y": .55,
      "end_scale_x": .15, "end_scale_y": .15,
      "start_rotation": -15, "end_rotation": 45,
      "interpolation": "ease_out"}
  }],
  "ambiances": [{
    "id": "emberfall", "name": "Emberfall", "native_ambient": "dust",
    "emitters": [{"particle": "ember", "count": 28,
      "area": {"x": 0, "y": -16, "width": 528, "height": 208},
      "velocity_x": {"min": -.08, "max": .08},
      "velocity_y": {"min": .12, "max": .34},
      "acceleration_x": 0, "acceleration_y": .0005,
      "rotation_speed": {"min": -.8, "max": .8},
      "particle_layer": 1, "blend": "additive", "mirror_with_room": true}]
  }],
  "defaults": {"room": {"ambient": "emberfall"}}
}

tint and scale_x/scale_y set the start color and size. Optional end_tint and end_scale_x/end_scale_y interpolate to exact values on the final visible lifetime tick; an omitted end axis inherits its start axis and an end scale may be zero. start_rotation and end_rotation are degrees and their transition is added to emitter rotation_speed. interpolation accepts linear (default), ease_in, ease_out, or ease_in_out. Lifetime fades multiply the resulting alpha. Colors use four finite channels in 0..1, scales use -64..64 (start scales cannot be zero), and rotations use -3600..3600 degrees.

Layers 0..4 mean front of players, behind players, behind normal terrain, behind background tiles, and furthest background. Limits are 64 particles, 32 ambiances, 16 emitters per ambiance and 512 lanes across the package. External particle PNGs must identify exactly one declared V2 sheet and the complete consecutive animation must fit it.

Custom ambiance is presentation-only. Each lane is derived from the pinned map identity, room, game tick, emitter and lane number without gameplay RNG or mutable simulation state. It is rollback-safe and covered by the normal map/asset online fingerprint; use map.lua or custom objects for gameplay behavior.

data.map grammar

; comments outside rows begin with ; or //
[center]
"@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@"
"                                 "
... exactly 10 more quoted rows ...
  • A header [room_id] starts each room.
  • Exactly 12 quoted rows follow; exactly 33 bytes appear inside each pair of quotes.
  • Leading/trailing spaces inside quotes are cells and must be retained.
  • Blank and comment lines are allowed only outside quoted rows.
  • V1 rejects unknown characters rather than silently treating them as empty.

Allowed V1 glyphs:

space ! # ( ) * + - . 1 2 : = ? @
A C E F G H I K L N O P Q S T W X Y Z
^ _ ` c e f i l m q s t u v w x | ~

V2 map-level tileset

"tileset": {
  "sprite_sheet": "tiles.png",
  "asset_sha256": null,
  "cell_w": 16,
  "cell_h": 16,
  "padding": 0,
  "native_layout": true,
  "tiles": []
}
sprite_sheet
A direct external PNG filename or builtin:sprites|tiles|misc|glyphs. Entries inherit it.
asset_sha256
Optional 64-hex external asset pin. The loader always computes the hash; omit this for normal authoring and all built-ins.
cell_w, cell_h
External grid cell dimensions, default 16, each 1..512.
padding
Inter-cell spacing removed during packing, default 0, range 0..64.
source_x/y, source_w/h
Optional usable rectangle inside a larger PNG. Origins default to 0; a width or height of 0 continues to the image edge. Only this rectangle must form a whole cell grid.
native_layout
External sheet only. When true, its first 128 row-major cells replace the native tile prefix for all unlisted ordinary glyph rendering. Extra cells are custom. Grid/image shape is otherwise unrestricted.
tiles
Zero to 64 symbolic definition objects. A native-layout-only package may leave it empty.

For per-room art, set defaults.room.native_tileset or rooms.<source-room-id>.native_tileset to a declared external PNG sheet name whose grid has at least 128 cells. A room override wins over the room default, then tileset.native_layout supplies the backward-compatible map-wide fallback. Omitted, empty, and null values inherit. Mirrored final rooms use their source room's sheet. This changes tile presentation only.

V2 requires a namespace-safe id: ASCII letters/numbers/._-, not beginning with dot/hyphen, maximum 43 characters (the runtime owner is map.<id>). Qualified tiles are map.<id>:<tile-id>.

At most 16 unique external sheet/grid configurations may appear in one package. Safe fallbacks exclude multi-cell generators, no-op/blank, waterfalls/back-fillers, and generic K. A custom symbol may itself be any printable byte because alias binding occurs before native generation.

Special behavior belongs in auto-discovered map.lua, not JSON. See the exhaustive map Lua API.

External asset rules

  • Direct filename in the package only: no slash, drive, absolute path, .., ADS, or reparse file.
  • Valid PNG signature/IHDR, nonempty, ≤64 MiB, dimensions 1..8192 each.
  • The selected source rectangle must fit and divide exactly after padding, contain at most 8,192 cells, and cover every frame range. The rest of the PNG may have any layout.
  • The bridge rechecks path/header/full SHA-256 immediately before decode/pack, strips padding into a tight grid, and refuses global native atlas overflow.
  • Missing/changed/invalid/unpacked assets remain unresolved and use the declared native fallback.

Online identity and atomic reload

A custom map advertises custom:<normalized-id>:<sig>. Signature input includes JSON, room text, loader-computed hashes of every external V2 sheet, and exact optional script bytes/bindings. Authors do not copy digests manually. Vanilla keys are vanilla:<index>.

Numeric selector positions are local and can change when packages are installed/reordered. The server matches stable keys and sends each client its own selector.

A successful scan atomically replaces the affected map/content owner set. A bad edit preserves the previous installed generation; a newly invalid package is skipped without blocking others. Active native pointers/script bind to a pinned generation until another map generation replaces them. Online rollback freezes reload.

Validation and conformance

  • Collect and log all recoverable issues with package/file/field location, offending value, expected rule, and final skip reason.
  • Hard parse failures still stop safely and never partially register a package.
  • V1 compatibility keys may warn when unknown; V2 tileset/definition keys reject unknown fields.
  • Native collision must remain valid even if custom visuals/script fail.
  • Optional behavior is one bounded direct map.lua, never JSON code.
  • Run tests/run_v2_map_test.ps1 and tests/run_map_script_test.ps1, then complete the fixed-address live test in the map guide.
