Security and trust boundaries

Yule combines injected native code, trusted Lua mods, sandboxed map scripts, Internet services, authenticated UDP gameplay, and a transactional updater. These components do not all provide the same isolation or guarantees.

This is a compatibility framework, not an anti-cheat or hostile-mod sandbox. Only install framework binaries and ordinary mods from publishers you trust.

Installed mods are trusted code

A mod's environment prevents accidental global-name collisions and attributes callbacks/assets/content to an owner. It is not intended to contain a malicious package. mod.dofile, standard Lua facilities, developer-console lua.file, filesystem pickers, and native framework APIs are powerful enough that a hostile package should be treated like any other program.

  • Review mod.json, entry scripts, and bundled binaries before installation.
  • Use mod.fs pickers rather than accepting arbitrary unvalidated paths from users.
  • Restrict mod.net/mod.http to known endpoints and bounded, expected responses. Native HTTP owner-scopes handles, cleans up on unload, and caps bodies at 8 MiB; set a lower application-level limit when your format needs less.
  • Do not place account passwords, bearer tokens, update keys, or shared netplay keys in config/storage/logs.
  • Content declared by gameplay-affecting mods participates in compatibility policy; cosmetic-only labeling is not a security guarantee.

See Lua mod API for exact filesystem/network limits and Configuration for persistence.

Map packages and deterministic scripts

V2 packages are scanned from direct, non-reparse subdirectories under maps/. Paths must remain package-relative; traversal, absolute paths, oversized assets, unsupported PNGs, and malformed JSON/map/script data fail closed. Package identity includes normalized gameplay-relevant metadata, layout/content and script/asset hashes so both online clients can require the same content fingerprint.

map.lua runs in a separate restricted environment: no ordinary mod I/O, no wall clock, no OS/process access, deterministic RNG only, bounded persistent state, bounded instruction work, and validated entity/tile/contact operations. Online entry fails closed if the deterministic script is not ready. A hot-reload error retains the last known-good package rather than installing half-parsed state.

Why tileset SHA-256 appears in identity: visual bytes can affect what a player can perceive, and a map-wide replacement must resolve identically between peers. It is content identity, not proof of a trusted author.

Full constraints are in Map package format and Map Lua API.

Online protocol security

Control connection

The server validates message shape, state transitions, account/session ownership, queue/challenge ownership, protocol tuples, exact game/framework build fingerprints, match membership, result-report eligibility, and timeouts. Keep the server and both clients on the advertised control/match/P2P tuple and identical game/framework binaries; a release label alone is not a compatibility proof.

The present Node service uses a raw TCP control protocol. Unless it is placed behind a deliberately compatible secure transport, messages are not protected by TLS. Do not transmit a plaintext password repeatedly; the client uses a login flow and saved credential mechanism described below. The optional admin UI is a separate passwordless default-loopback listener: private bind/source addresses are its authorization boundary, while automatic session cookies, CSRF tokens, and POST-only changes prevent cross-site browser actions. Keep it on the operator's trusted LAN or SSH tunnel and never expose its port publicly.

Gameplay transport

P2P v17 consumes a server-issued or manually armed per-match key and authenticates packet envelopes. Direct debug host/join accepts the key only through a one-shot clipboard operation, clears the clipboard before arming, never logs/persists it, and consumes it on successful start. Relay packets retain the match boundary; the relay is a fallback route, not a globally open UDP forwarder.

Packet authentication prevents unauthenticated modification/forgery within its design. It does not encrypt inputs, endpoints, or metadata. Netplay remains peer-to-peer when direct routing works, so each peer can learn the other's public endpoint.

Fairness and cheating

Checksums, deterministic content fingerprints, build/protocol checks, and host-authoritative correction detect or recover classes of accidental divergence. A client running arbitrary native code can still cheat, lie about presentation, or inspect local memory. Ranked operation needs server-side policy, abuse controls, monitoring, and an explicit enforcement design beyond rollback synchronization.

Accounts and local credentials

“Remember me” stores the reusable online secret using Windows Credential Manager, not mods/online_hub.cfg. With a valid saved login, startup/deep-link flow can authenticate in the background and proceed directly to the intended hub route. The config contains non-secret endpoint/preferences only.

  • Never copy credential blobs into support reports or commit them.
  • Do not log passwords, session tokens, match keys, reset tokens, or complete private endpoints.
  • Remove the saved credential through the application's account flow or Windows credential UI when rotating access.
  • Protect online_server/users.json and ratings.json; deployment updates must preserve them and backups must have restrictive permissions.

Updater integrity and recovery

The update client requires HTTPS except explicit loopback development URLs, validates strict channel metadata, downloads to staging, checks every declared SHA-256 and size, and refuses unsafe relative paths, replacement outside the install root, reparse-point traversal, unexpected/missing files, and malformed transactions. Replacement happens in a small one-shot YuleUpdater.exe after the exact game process exits.

A journal records the whole replacement set. On interruption, the helper completes or restores the set rather than mixing versions; committed cleanup is retried on a later handoff. A same-install process guard prevents two instances from replacing mapped DLLs concurrently. Relaunch arguments are forwarded as arguments, not reconstructed shell text.

Publish payloads first and latest.json last. Upload the channel pointer atomically only after every versioned file is reachable and its hash/size matches. Never test recovery on the only copy of an installation.

Current integrity ultimately trusts the HTTPS channel and hashes it declares. For stronger publisher authenticity, sign the manifest with an offline key and pin the verification public key in the client. See Updater and release publishing.

yule:// deep links and single instance

The protocol handler normalizes the process working directory to the executable directory and accepts only known, bounded routes such as hub, requests, queue, and challenge intents. Malformed/unknown routes fail closed. A secondary launch forwards a validated intent to the existing game instance; it should not blindly pass arbitrary command lines, paths, or script content.

  • Treat every web-originated route as untrusted input even when it comes through your own redirect page.
  • Require login and state validation again inside the receiving game; a link is navigation intent, never authorization.
  • Challenge identifiers/usernames must be encoded, length-limited, and resolved by the server rather than interpreted as executable content.
  • A redirect page may attempt to close itself after launching the protocol, but browsers can refuse to close tabs they did not open via script.

Discord LFG, Rich Presence, and server deployment

Rich Presence intentionally publishes only coarse activity. It must not expose account names, opponents, maps, match ids, ratings, endpoints, tokens, or private queue/challenge details. The Discord application id is public; bot tokens are secret.

The LFG bridge must keep its Discord bot token and server bridge credential in service environment variables, scope posting to configured channels, avoid mentions by default, obey rate limits, and redact match/account network data. Queue messages are delayed to avoid transient spam and edited in place; a direct challenge must not create a public queue post.

Run Node services as an unprivileged dedicated user, keep secrets/data outside replacement sets, validate all environment variables at startup, set firewall rules only for required ports, rotate logs, and back up durable account/rating data. The provided JSON-file server is a small deployment, not a horizontally scalable durable database. See Server deployment and Discord integration.
